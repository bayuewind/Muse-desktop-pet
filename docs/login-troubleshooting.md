# 登录故障反馈

适用于 Muse 桌宠 0.2.1 及之后带诊断导出功能的版本。0.1.1 没有保存完整的登录失败原因，需安装新包后重新复现。

## 提交步骤

1. 安装新包前，从托盘菜单退出旧桌宠。无需卸载、删除本机数据或退出日常浏览器账号。
2. 启动新包，从桌宠的账号菜单登录，在它弹出的专用窗口中完成登录。
3. 若未自动连接，点击一次「账号 → 手动检查并连接（备用）」。
4. 在错误弹窗点击「导出诊断报告…」，或从「账号 → 导出脱敏诊断报告…」保存 JSON 文件。
5. 将 JSON 和下方填写的反馈一起发给维护者。公开提交前检查截图，遮挡姓名、邮箱和聊天。

请在退出桌宠前导出。记录只在内存中保留本次运行最近 150 条事件；重启会丢失旧记录。报告不会自动上传。
保存时请选择新文件名，导出不会覆盖已有文件。

## 系统代理（0.2.2 起）

桌面程序通过 Electron 解析操作系统代理设置，再为原生 HTTPS 和 WebSocket 建立对应的代理连接。
支持 HTTP CONNECT、HTTPS 代理和 SOCKS；不会写死 FlClash 等软件的端口，也不会修改系统代理设置。
代理由用户系统配置决定；TUN 接管与应用显式选择代理是两回事。

使用 FlClash 等工具时，先确认其「系统代理」开启，再启动新桌宠进行验证。只有 TUN 开启、
而系统代理返回直连时，报告会显示 `direct`；这不代表 TUN 没有接管。

报告新增：

- `proxy_resolve`：解析系统代理，`transport` 区分 `https` 与 `wss`。
- `route`：`direct`、`http_proxy`、`https_proxy` 或 `socks_proxy`，只表示选择的路径。
- `network_request`：请求结果；必须结合状态和错误码判断连接是否成功。
- `proxy_resolution_failed` / `proxy_resolution_timeout`：代理解析失败 / 超时。
- `proxy_type_unsupported` / `proxy_configuration_invalid`：不能使用的代理类型 / 配置。

每次新请求或网关重连重新解析设置。仅使用返回列表的首选路径；代理不可用时不会偷偷回退直连。
需要账号密码的代理若返回 HTTP 407，将报告失败，目前不提供代理凭据输入框。
TLS、VM 分配和 Noise 身份验证仍然保留。报告不记录代理地址、端口、PAC 地址或代理认证信息。
独立 Node 开发 CLI 不通过桌面程序初始化，仍保留其原有网络行为。

## 隐私边界

报告包含应用、运行环境和浏览器版本、时间、登录阶段、固定错误码、可用的 HTTP 状态、白名单内的网络错误码和验证结果布尔值。
不包含 Cookie、Token、账号/VM 标识、服务器地址、文件路径、完整异常栈、聊天或网页内容。
不要提交 `%APPDATA%\MuseDesktopPet` 整个目录、`native-session.enc`、`AccountLogin-*`、浏览器配置、HAR 或恢复私钥。

## 阶段解读

| 阶段 | 排查方向 |
| --- | --- |
| `browser_start` / `readiness` | 专用浏览器启动、页面加载、是否读到必要的登录元数据 |
| `metadata` / `target` | 网页结构或 VM 元数据是否与适配器兼容 |
| `vm_policy` | 当前账号是否要求尚未支持的 VM 证明；不能跳过校验 |
| `cookies` | 专用会话中是否有符合要求的 Muse 登录 Cookie |
| `session` / `assignment` | 原生请求、会话有效性、官方分配信息是否一致 |
| `token` | 官方网关令牌申请 |
| `gateway` / `peer_identity` / `ping` | 网关网络、身份验证、应用层连通性 |
| `browser_cleanup` / `vault_save` | 专用窗口清理、本机加密存储 |

阶段用于缩小范围，不等于根因。网页登录成功不能证明原生网络路径也可用。
本版本新增诊断能力，不代表已经修复所有登录失败。
